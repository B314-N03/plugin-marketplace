# Deck Arcs

Pick the arc for the chosen shape and copy it into the brief. The pattern numbers refer to `marp-deck`'s `reference/slide-patterns.md`. Adjust to the slide count; one idea per slide.

## Deep-dive (one feature)

| # | Slide | Pattern |
|---|---|---|
| 1 | Title: feature name, vendor, version or date | 1 lead |
| 2 | What it is: one-sentence definition plus status, plan tier and platforms | 2 definition |
| 3 | Problem it solves: before vs after | 3 matrix |
| 4 | How it works: flow or mechanism | 3 or 4 |
| 5 | Setup and config: the exact keys, flags or commands | 5 code |
| 6 | In practice: an example run or output | 4 or 5 |
| 7 | Limits and caveats: beta status, cost, known gaps | 4 |
| 8 | Comparison with what we use today, or with the alternative | 3 matrix |
| 9 | What it means for us (repo or org-wide, per the brief's Scope): impact, rollout and recommendation | 4 |
| 10 | Closing: one-line verdict | 6 lead |
| 11 | Sources | 7 |

## Roundup (several changes, one window)

| # | Slide | Pattern |
|---|---|---|
| 1 | Title: "What's new in <tool or stack>, <window>" | 1 lead |
| 2 | At a glance: table of every item (change, version or date, impact) | 3 matrix |
| 3–8 | One slide per top item: what it is, how to use it, and one config or code line | 4 or 5 |
| 9 | Smaller changes worth knowing, as a bullet list | 4 |
| 10 | What it means for us: adopt / trial / ignore per item | 3 matrix |
| 11 | Sources | 7 |

## Upgrade highlights (installed version to latest)

| # | Slide | Pattern |
|---|---|---|
| 1 | Title: "<pkg> <installed> → <latest>" | 1 lead |
| 2 | Version timeline: the releases in between, with dates | 3 matrix |
| 3 | Breaking changes, with a code before/after | 5 code |
| 4–7 | Headline features, one per slide | 4 or 5 |
| 8 | Migration steps for our repo | 4 |
| 9 | What it means for us: effort, risk and recommendation | 4 |
| 10 | Sources | 7 |
